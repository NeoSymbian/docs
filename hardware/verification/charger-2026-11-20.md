# Charger watchdog check — 2026-11-20

Question (D2, [hardware.md](../README.md)): our battery driver only reads the PM660. It never pets the
charger's watchdog. If ABL leaves the watchdog armed, could charging stop on its own?

**Answer: no. The watchdog is off.** No PMIC write was added.

## Register facts

From msm-4.9 `drivers/power/supply/qcom/smb-reg.h` and `qpnp-smb2.c` (LineageOS
`android_kernel_google_msm-4.9` at `649b0b6508be`, the Pixel 3a kernel). PM660 SID 0, CHGR `0x1000`, MISC `0x1600`.

| Register | Bits |
|---|---|
| `0x1651` WD_CFG | b7 trigger AFP, b6 bark int, b5 bite int, b4:3 SFT after IRQ, b2 IRQ SFT, b1 timer on plug-in, b0 timer on |
| `0x1653` SNARL_BARK_BITE_WD_CFG | b7 bite disables charging, b6:4 snarl, b3:2 bark, b1:0 bite timeouts |
| `0x1643` BARK_BITE_WDOG_PET | b0 pet |
| `0x160c` WDOG_STATUS | b0 bark/bite status |
| `0x1610` MISC INT_RT_STS | b7 switcher power OK, b1 bark, b0 snarl |
| `0x1051` CHGR_CFG2 | b7 charge-enable source (1 = pin), b6 polarity, b2 AUTO_RECHG, b0 charger inhibit |

Android (`smb2_init_hw`) sets the timeouts with bit 7 of `0x1653` clear (a bite does not stop charging), enables
the watchdog on plug-in with the bark interrupt, and pets it from the bark handler. PM660's smb2 charger has no
separate fast-charge safety-timer register (the `0x10a0` timer is smb5's).

## Phone reading

Pixel 3a XL, RAM boot already running (kernel monitor over USB, Mac USB port), plugged in, battery full. Read-only
`spmi r 0 <addr>` and `battery`:

| Register | Value | Meaning |
|---|---|---|
| `0x1651` | `0x00` | watchdog off, not armed on plug-in, no bark/bite interrupts |
| `0x1653` | `0x0c` | a bite would not stop charging (and the watchdog isn't running) |
| `0x160c` | `0x01` | bark/bite status bit set: meaning not documented, likely latched; recheck after a cold boot |
| `0x1610` | `0x80` | switcher power OK; no bark, no snarl |
| `0x1006` | `0x46` | phase 6 = inhibit (charged, holding), soft-terminated |
| `0x1007` | `0x00` | no battery overvoltage |
| `0x1051` | `0xc3` | charging enabled by the pin, inhibit on, AUTO_RECHG clear |
| `0x1061` | `0x50` | fast-charge current 2.0 A |
| `0x1070` | `0x79` | float voltage ≈ 4.395 V |
| `0x1310` | `0x10` | USB present |

`battery`: present, 100 %, 4 347 645 µV, USB present and online, state 4 (full).

## Open

- **Recharge after full:** `AUTO_RECHG` is clear and the bit's polarity isn't documented in the header. Charge
  overnight on the installed slot and read Settings → Battery history: if the level stays at 100 %, recharge
  works; if it slides down while plugged in, it doesn't.
- `WDOG_STATUS` bit 0 on a cold boot (after a full power-off), with the new `battery` line.

## Change

kernel `charger/watchdog-status`: the monitor's `battery` command prints one more line,
`battery charger watchdog: cfg= timeouts= status= misc rt=; CHGR_CFG2=`. Checks:
`tools/test-battery-host.py` passes; `neo kernel bonito` builds (atlas). Phone RAM boot of that image (slot a,
successful, no retry spent), plugged in, full:

```
battery charger watchdog: cfg=0x0 timeouts=0xc status=0x1 misc rt=0x80; CHGR_CFG2=0xc3
```

The same values as the raw reads above. `WDOG_STATUS` bit 0 is still set after a warm reboot, so it is latched or
constant; a full power-off is still to check.
